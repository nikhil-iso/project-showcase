# AI Context For Future Agents

This file explains how this portfolio website works and how to safely work on it. Read this before making changes.

## High-Level Purpose

This is Nikhil Patel's electrical engineering portfolio website.

It presents:

- a homepage with profile/about content and personal projects
- a team projects page with rocketry, robotics, and hackathon work
- downloadable PDFs for CV, resume, and portfolio
- project detail slide-over panels with text, images, and videos

The production domain is:

```txt
https://www.nikhil-eng.com
```

The canonical origin is defined in:

```txt
src/lib/site.ts
```

## Media System

The site now uses Vercel Blob for large public images/videos.

Simple mental model:

- Vercel Blob stores the real files.
- `src/lib/media.ts` stores the public URLs and metadata.
- Pages use `media.someName` instead of raw filenames.
- `media-source/` holds original local files.
- `media-dist/` holds generated optimized/upload-ready files.

Important:

- `media-source/` is ignored by Git.
- `media-dist/` is ignored by Git.
- `.env.local` is ignored by Git.
- Do not commit original full-size media or Blob credentials.

The public Blob base URL is in:

```txt
src/lib/media.ts
```

The base URL itself is public and not a secret. Blob read-write credentials are secret.

## Secret And Security Rules

Never commit:

```txt
.env
.env.local
.env.production
.env.development
media-source/
media-dist/
.codex-remote-attachments/
```

`.gitignore` is configured to ignore these.

Blob upload credentials are expected locally in `.env.local`:

```txt
BLOB_STORE_ID="..."
BLOB_READ_WRITE_TOKEN="..."
```

Do not paste, print, log, commit, or include the token in docs.

If a Blob token is ever shown in chat, screenshot, terminal output, or committed by mistake:

1. Go to Vercel.
2. Open the Blob store.
3. Go to settings.
4. Restore/regenerate credentials.
5. Replace local `.env.local` with the new values.

The website only needs public Blob URLs at runtime. It does not need the read-write token to display images.

## Existing Vercel Blob Migration

Displayed images/videos were moved out of `public/`, optimized/uploaded, and referenced through:

```txt
src/lib/media.ts
```

Scripts:

```txt
scripts/optimize-media.mjs
scripts/upload-media.mjs
```

Package scripts:

```json
"media:optimize": "node scripts/optimize-media.mjs",
"media:upload": "node scripts/upload-media.mjs"
```

`sharp` is used as a dev dependency for optimization.

Image behavior:

- JPG/PNG/JPG sources are converted to WebP.
- Normal images max out at 1200px wide.
- Profile image maxes out at 512px wide.
- WebP quality is usually 78.
- Profile quality is 82.
- Images are not enlarged.
- EXIF orientation is handled with `rotate()`.
- Output dimensions are written to `media-dist/manifest.json`.

Video behavior:

- Videos are copied unchanged to `media-dist/videos/`.
- Videos are uploaded to Blob as public MP4 files.

## How To Add A New Image

1. Put the original image in:

```txt
media-source/
```

Example:

```txt
media-source/my-new-photo.jpg
```

If the folder does not exist on a new machine, create it beside `src`, `public`, and `package.json`.

2. Open:

```txt
scripts/optimize-media.mjs
```

3. Find:

```js
const imageAssets = [
```

4. Add an entry:

```js
{
  key: "myNewPhoto",
  source: "my-new-photo.jpg",
  output: "my-new-photo.webp",
},
```

Rules:

- `key` is the internal name used in manifests/scripts.
- `source` must exactly match the original filename in `media-source/`.
- `output` is the optimized WebP filename uploaded to Blob.
- Use lowercase/kebab-case output names.

5. Run:

```powershell
npm run media:optimize
npm run media:upload
```

6. Open:

```txt
media-dist/manifest.json
```

Find the asset and copy its generated `width` and `height`.

7. Add it to:

```txt
src/lib/media.ts
```

Example:

```ts
myNewPhoto: image("my-new-photo.webp", "Short helpful alt text", 1200, 800),
```

8. Use it in a route:

```ts
{ type: "image", ...media.myNewPhoto, caption: "Figure 1: My new photo." }
```

## How To Replace An Existing Image

Preferred safe approach:

1. Add the new original file to `media-source/`.
2. Give it a new output filename, for example:

```txt
project-up-boat-tail-v2.webp
```

3. Run:

```powershell
npm run media:optimize
npm run media:upload
```

4. Update only the matching entry in `src/lib/media.ts`.

Why use a new filename:

- Blob URLs are public and cacheable.
- New filenames avoid browser/CDN cache confusion.

Do not overwrite old Blob objects unless you intentionally want to manage cache invalidation.

## Working On Another Machine

Normal website editing does not require `.env.local`.

On a different machine:

```powershell
git pull
npm install
npm run build
```

You only need `.env.local` on that machine if you want to upload new/replacement media to Vercel Blob.

If you need uploads, create:

```txt
.env.local
```

with:

```txt
BLOB_STORE_ID="..."
BLOB_READ_WRITE_TOKEN="..."
```

Get those values from the Vercel Blob store quickstart/settings page. Never commit them.

## Build And Verification Checklist

After code/media changes:

```powershell
npm run media:optimize
npm run media:upload
npm run build
```

For simple code-only changes:

```powershell
npm run build
```

Useful checks:

```powershell
git status --short
git diff --stat
git diff --cached -G"vercel_blob_rw_|BLOB_READ_WRITE_TOKEN=|VERCEL_OIDC_TOKEN=" --name-only
```

Expected:

- no Blob secrets in staged files
- no `.env.local` staged
- no `media-source/` staged
- no `media-dist/` staged
- public image/video files are not reintroduced unless intentionally small/static
- build passes

To spot old local media references:

```powershell
rg -n "profile-picture|usst_welcome|ARTS_prototype|PXL_20260528|SimuLight Wide|Sunrise Alarm|SimuLightPCB|MacroKeyboard|Macropad|USST_AGM|USST_Rocketry|Project Up|4627Thor|4627logo|skillsbot" src -S
```

Matches in human text or `src/lib/media.ts` can be okay. Old route-level `src: "/some-image.jpg"` references should be replaced with `...media.someKey`.

## Known Local State / Gotchas

- `media-source/` and `media-dist/` are local-only and will not appear on a fresh clone.
- `.env.local` is local-only and will not appear on a fresh clone.
- `src/routeTree.gen.ts` may appear modified after builds because of generated/line-ending noise. Inspect with `git diff` before staging.
- Vercel Blob public URLs are allowed in code. Blob write tokens are not.
- If a future agent needs to upload media, it must have a local `.env.local` with valid Blob credentials.
